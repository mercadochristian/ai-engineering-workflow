# Work update

Author: [Christian Mercado](https://github.com/mercadochristian).

AI-assisted instructions. Behavioral reliability across agents and projects
remains unverified.

Use the named task, audience and requested period. Resolve relative dates in the
owner's timezone. Reuse an existing authorized source scope; do not collect new
private sources merely because they are connected. Ask only when a missing fact
would materially change the draft.

With enough evidence, write directly. If decisions or outcomes need recovery,
perform a bounded lookup or use work-context-brief when available, reading its
current instructions. This skill remains usable without another installed skill
or a particular team or tracker.

## Assess the evidence

Attribute work to the actual contributor and deduplicate the same change across
tickets, commits, reruns and summaries. Distinguish planned, implemented, locally
checked, deployed, verified and awaiting approval. Use the strongest matching
evidence while retaining later corrections and failures.

Do not infer completion from a plan, a merge request, collected tests, upload
acceptance or an older revision's successful execution. Preserve the tested
revision, target and relevant local changes when they affect the claim. Report
passes against known scope/denominators, keeping failed, blocked, unrun/manual
coverage and cleanup/restoration gaps visible. Missing evidence remains unknown.

Reconcile conflicts by revision, target and scope before combining results.
Describe a material discrepancy and the next verification needed. Never invent
progress, approvals, ownership, dates, ETAs, measured savings or test outcomes.

## Write for the reader

Lead with the result or current position, then explain important unfinished work
and the next action. A short paragraph often suffices; Progress/Next/Blockers is
useful for a standup. Include relevant links without reproducing an audit log.
Keep qualifications beside the claim, such as local checks passed with live
validation unrun. A fresh task with no progress should say so plainly.

Label an entire simulated update and its selected scenario. Treat fictional
milestones as assumptions, not actual contributions or live task state. A final
simulation step does not establish implementation, QA approval or release.

Return a draft in chat by default. Sending, publishing, saving a service-side
draft, changing task status or scheduling requires its own applicable authority.
Filter private detail for the intended audience. An update adds no delivery
stage or approval gate and cannot turn incomplete evidence into acceptance.
