# Task checkpoint

Keep the filled checkpoint private and reuse its task ID and location. Update
current state in place; do not create a new checkpoint for every session.

Updated: date and timezone
Status: investigating / implementing / verifying / blocked / complete

## Goal and latest direction

Requested outcome, acceptance criteria, approved scope changes, and remaining work.

## Decisions and authorization

Decisions and reasons, allowed actions, and explicit restrictions. This checkpoint
records authority; it does not grant it.

## Current state

Repository, branch, revision, changed files, and unrelated work to preserve.

## Evidence and limits

Exact commands, targets, outcomes, and private evidence locations. Identify checks
invalidated by later changes and separate observations from hypotheses.

## Blockers and failed approaches

What was tried, what happened, why it was rejected, and what would unblock progress.

## Next action

One concrete next operation. On resume, verify current source and Git state first.
